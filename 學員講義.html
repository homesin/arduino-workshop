§2今天的流程

每一段都以「看得到結果」收尾。落後了先求會動，細節可以回家補 —— 講義你帶得走，現場的三小時帶不走。

先讓一顆燈聽話

0:00 – 0:55
0:00步驟 1

確認板子能燒錄

接上 USB，Arduino IDE 選工具 → 開發板 → Arduino Uno，再選工具 → 連接埠 （選有 COM 編號的那一個）。開檔案 → 範例 → 01.Basics → Blink，按上傳。

檢查點板子上標示 L 的小燈開始一秒一閃。
0:15步驟 2

看懂 setup 與 loop

一支 Arduino 程式永遠只有三塊：最上面的宣告區、開機只跑一次的 setup()、以及跑完 setup 後無限重複的 loop()。 閃爍的節奏就寫在 loop 裡。

試著把 delay(1000) 改成 delay(200) 再上傳一次， 感覺一下「改程式 → 上傳 → 硬體行為改變」這個循環。

0:30步驟 3

接一顆自己的 LED

LED 長腳是正極，串一顆 220Ω 電阻接到 D9；短腳是負極，接到 GND。 電阻本身不分方向。接線前先拔掉 USB。

把程式裡的腳位從 13 改成 9，上傳。

檢查點你自己接的那顆燈開始閃，不是板子上的 L 燈。
0:42步驟 4

從「開關」變成「呼吸」

digitalWrite 只有 HIGH 和 LOW 兩種狀態。 換成 analogWrite，值可以是 0 到 255，用 for 迴圈慢慢加上去再慢慢減下來， 看起來就像在呼吸。

只有腳位旁邊有 ~ 記號的才支援：D3、D5、D6、D9、D10、D11。這也是我們選 D9 的原因。

檢查點燈的亮度連續變化，看不出一格一格的跳動。

讓資料離開這塊板子

0:55 – 1:45
0:55步驟 5

換上感測器

拔掉 USB，把三個模組接上去（腳位表見 §3）。LED 留在 D9 不用拆，兩者不衝突。

開啟桌面 arduino-workshop 裡的 arduino-cloud-workshop/arduino/sensor_node/sensor_node.ino，上傳。 需要的 SimpleDHT 函式庫一鍵安裝已經裝好；編譯時說找不到它的話， 到工具 → 管理程式庫搜尋 SimpleDHT 安裝（作者 Winlin）。

開序列埠監控視窗，右下角速率選 9600。

檢查點每秒跳出一行像這樣的資料：
{"t":26,"h":58,"pir":0,"flame":812}
1:10步驟 6

Node.js 把資料接過來

先把序列埠監控視窗關掉。一個 COM 埠同時只能被一個程式使用 —— 這是今天最常見的錯誤，等一下 §5 會再提醒一次。

在專案資料夾開命令提示字元：

npm run ports        ← 看看板子在哪個 COM 埠

用記事本打開 .env（一鍵安裝已經從 .env.example 複製好），填入你的埠號：

SERIAL_PORT=COM4

然後啟動：

npm start
檢查點終端機出現「收到第一筆資料，接下來每秒一筆」。
1:25步驟 7

即時儀表板

瀏覽器開 http://localhost:3000。溫度、濕度兩條曲線會即時往前走， 滑鼠移上去可以看到任一時間點的數值。

對著 DHT11 呵一口氣，看濕度那條線衝上去。這是第一個去處：看現在 —— 資料完全不出這台電腦，所以沒有任何額度限制。

檢查點呵氣時濕度曲線明顯上揚，幾秒後慢慢回落。

存起來，以及叫人

1:45 – 3:00
1:45步驟 8

上傳 ThingSpeak

把事前作業拿到的 Write API Key 填進 .env：

THINGSPEAK_WRITE_KEY=你的金鑰

Ctrl+C 停掉程式再 npm start 重新啟動。 程式已經內建 15 秒節流，不會超過免費方案的速率限制。

回 ThingSpeak 頻道頁面，到 Sharing 分頁選「公開」， 這樣別人不用登入就看得到你的圖表。這是第二個去處：存起來。

檢查點終端機出現「ThingSpeak 已收第 N 筆」，網頁圖表開始長出資料點。
2:15步驟 9

讓手機響起來

把 LINE 的 Channel access token 填進 .env，重新啟動程式。

LINE_CHANNEL_ACCESS_TOKEN=你的權杖

用手在 PIR 感測器前面揮一下，或拿打火機（不要點火，靠近就好）測試火焰感測。

這是第三個去處：出事叫人。程式用的是「群發給所有好友」， 所以不需要知道任何人的 ID，也不需要對外開通道 —— 只是一個往外的 HTTPS 請求。

檢查點手機收到 LINE 通知，儀表板右下角同時出現一筆通報記錄。
2:45步驟 10

校正與收尾

火焰門檻一定要照 §4 校正過才算完成。剩下的時間調整你自己的警報文字， 或試著把門檻改成「溫度超過 30 度就通知」。

§3接線表

三個模組都帶排針，用母／母杜邦線直接插上 Uno 就好，這一段不需要麵包板。 接線前一定要先拔掉 USB。

模組VCCGND訊號腳說明
DHT11 溫溼度5VGNDD2 反應慢，一秒讀一次就好
HC-SR501 人體紅外線5VGNDD3 數位輸出，有人時變 HIGH
火焰感測5VGNDA0 類比輸出，接 AO 那一腳
LED + 220Ω 電阻—GNDD9 上一段留下來的，可以不拆

接線前先拔 USB

帶電接線如果不小心讓兩支腳位碰在一起，可能燒掉那支腳位甚至整塊板子。 先斷電、接完檢查一次、再插上 USB —— 這個順序不要換。

§4火焰門檻要現場校正

.env 裡的 FLAME_THRESHOLD 預設是 400， 但每一顆感測器、每個場地的環境光都不一樣。照抄預設值上場，多半不會準。

正確做法是先跑起來，看儀表板上的「火焰感測 A0 原始值」：

狀況典型讀值你的實測
平常（沒有火源）700 – 1000________
打火機靠近約 20 公分100 – 300________
取兩者中間值當門檻≈ 400________

把自己量到的中間值填回 .env，重新啟動程式。 數值越低代表越接近火源，所以程式判斷的是「低於門檻就警報」。

§5卡住的時候

這張表涵蓋現場八成的狀況。先照著查，查不到再舉手。

症狀原因怎麼解
上傳失敗，寫著
Access denied		 COM 埠被別的程式占用 關掉序列埠監控視窗，或到終端機按 Ctrl+C 停掉 Node.js。 一個 COM 埠同時只能有一個程式使用。
連接埠選單裡沒有 COM 選項 驅動沒裝，或線只能充電 換一條確定能傳資料的 USB 線；再不行就重裝 CH340 驅動。
Node.js 說
連接埠 3000 已經被占用		 上一次的程式還在跑 找到另一個終端機視窗按 Ctrl+C，或在 .env 把 PORT 改成 3001。
溫濕度一直是 0 DHT11 訊號腳接錯，或讀太快 確認接在 D2。DHT11 需要至少一秒一次，程式已經處理，不要自己改快。
PIR 一直說有人 模組上的延遲時間旋鈕轉太大 HC-SR501 上有兩顆小旋鈕，把「延遲時間」那顆逆時針轉到底。 另外它開機後需要約一分鐘暖機。
ThingSpeak 回傳 0 Write Key 貼錯，或送太快 確認貼的是 Write API Key 不是 Read。程式已內建 15 秒節流。
LINE 回 401 權杖錯了或已失效 回 LINE Developers 重新產生 long-lived token，注意不要複製到多餘的空白。
LINE 回 429 這個月的免費額度用完了 免費方案每月 200 則。等下個月，或改用自己的另一個帳號。
燈完全不亮 九成是正負腳接反 LED 長腳是正極。把它轉個方向再試 —— 這是最常見的一項。

為什麼每個人要有自己的 LINE 官方帳號

LINE 群發訊息是「發給 N 個好友就扣 N 則」，免費方案每個月只有 200 則。 如果全班共用一個帳號、有 10 個人加好友，一次測試就扣 10 則 —— 200 則只夠測 20 次。 現場除錯一個人就可能試十次。

用自己的帳號，你有完整的 200 則，而且結訓後帳號帶得回自己單位繼續用。

§6回家可以往哪裡走

這四條路都沿用今天的接線與程式骨架，差別只在多接一個零件或多改幾行。

方向要多什麼改哪裡
溫度也發警報 不用多任何零件 src/index.js 裡照著火焰那段，加一個「溫度大於 30 就通知」。最快的一條。
加一顆按鈕 輕觸開關、10KΩ 電阻 Arduino 端用 digitalRead 讀按鈕狀態，多送一個欄位上來。
換成問答機器人 需要對外的 HTTPS 通道 改用 LINE 的「回覆訊息」——回覆完全免費且無限， 學生問「現在幾度」隨你玩。代價是要架 webhook。
讓裝置獨立上網 ESP32 開發板 不用接電腦就能自己連 WiFi。但機關的 WiFi 常需要網頁登入， ESP32 過不了，實務上多半得用手機熱點。
