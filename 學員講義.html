Arduino 感測器與雲端監測實作手冊

今天要做一台會自己回報的環境監測站：四個感測器量溫濕度、距離、有沒有人、亮暗， 數字顯示在螢幕上、存進 ThingSpeak 雲端，有東西靠近時手機收到 ntfy 通知。零基礎可以跟著做。

時長
約 6–7 小時（可彈性調整）
設備
每人一套
開發板
Arduino Uno R3
需要網路
是

§1建議上課前先做好

這四項能先做完最好，現場會順很多。沒時間先做也沒關係： 安裝軟體課堂上一開始會一起裝（邊裝邊上第一章），其他項目到時候再補。遇到問題先問，不要留到最後。

0 / 4 完成

主題名稱就是密碼

ntfy 沒有帳號也沒有登入：任何人知道你的主題名稱，就能訂閱它，也能對它發訊息。 所以要自己取、要夠難猜，全班不能共用同一個主題，也不要貼在群組裡。

§2你手上的零件

這些就是今天會用到的全部零件。沒有 LED、電阻、按鈕 —— 輸出會用「螢幕上的數字」和「手機通知」代替。

零件今天用來做什麼
Arduino Uno R3（CH340 版）主控板，負責讀感測器、整理成資料送給電腦
DHT11 溫濕度量溫度與相對濕度
HC-SR04 超音波量前方物體的距離（公分）
HC-SR501 人體紅外線偵測有沒有人在移動
LM393 光敏模組量光線亮暗（越暗數字越大）
400 孔迷你麵包板分電：讓四個感測器共用 5V 與 GND
杜邦線（母對公、公對公）母對公：模組接板子；公對公：Uno 的 5V、GND 接到麵包板電源軌

§3今天的流程

每一段都以「看得到結果」收尾。時間是預估，落後了先求會動，細節可以回家補 —— 講義你帶得走，現場的時間帶不走。

二、確認環境

約 0:15
0:00步驟 1

現場只做驗收

環境（課前或上課一開始）已經裝好了。現在把 Uno 用 能傳資料的 USB 線 接上電腦， 打開 Arduino IDE，選工具 → 開發板 → Arduino Uno，再選工具 → 連接埠（選有 COM 編號的那一個）。

連接埠一直不出現：先換一條 USB 線（最常見），再確認 CH340 驅動有裝。

檢查點工具 → 連接埠 裡看得到一個 COM 編號。

三、基礎操作

約 0:30 – 1:30
0:30步驟 1

讓板上的燈閃起來

在 IDE 開啟教材的 範例程式\c03a-blink，按上傳。這支程式不用接任何線， 用的是板子內建的 L 燈（接在 D13）。

試著把 delay(1000) 改成 delay(200) 再上傳，感覺「改程式 → 上傳 → 硬體改變」這個循環。

檢查點板子上標示 L 的小燈開始閃，改了 delay 之後閃得更快。
0:50步驟 2

看懂程式三段

一支 Arduino 程式永遠只有三塊：最上面的宣告區、開機只跑一次的 setup()、 跑完 setup 後無限重複的 loop()。閃爍的節奏就寫在 loop 裡。

1:00步驟 3

讓板子說話

開啟 範例程式\c03b-serial-hello，上傳。接著開工具 → 序列埠監控視窗（Ctrl + Shift + M）， 右下角速率選 9600。

看到亂碼：幾乎都是速率沒選 9600。之後所有感測器的數字，都是用這個視窗看的。

另外兩樣新工具，請看簡報：麵包板（哪些孔相通）和杜邦線（公對公、母對公）。

檢查點序列埠監控視窗出現「你好，我是 Arduino」和一直增加的次數。

四、感測器個別實作

約 1:30 – 3:30
1:30步驟 1

DHT11 溫濕度

先拔掉 USB 再接線。每個感測器的 VCC 先接 Uno 的 5V、GND 接 GND，訊號腳如下：

感測器腳位接到 Uno說明
DATAD2溫濕度資料線
VCC5V電源
GNDGND接地

針腳順序以模組板上的印字為準（S／DATA、+／VCC、-／GND），不同廠牌排列可能不同。 上傳 範例程式\c04a-dht11，開序列埠監控視窗。

動手：對著感測器呵一口氣，看濕度衝上去再慢慢回落。DHT11 反應很慢，要等幾秒。

檢查點序列埠出現「溫度 ○ °C　濕度 ○ %」，呵氣後濕度會上升。
2:00步驟 2

HC-SR04 超音波

感測器腳位接到 Uno說明
TrigD4發射
EchoD5接收回波
VCC5V電源
GNDGND接地

上傳 範例程式\c04b-hcsr04。動手：手掌放在探頭前 10–30 公分，慢慢靠近、再移遠。

一直是 -1（量不到）：先查 VCC、GND、Trig、Echo 四條線，再確認前方不是空曠（超過約 4 公尺也會量不到）。

檢查點手越靠近，距離數字越小；小於 30 公分會出現「有東西靠近」。
2:30步驟 3

HC-SR501 人體紅外線

感測器腳位接到 Uno說明
OUTD3有人／沒人
VCC5V電源
GNDGND接地

上傳 範例程式\c04c-pir。剛插電要暖機約一分鐘，這段時間的讀值不準。 暖機後在感測器前揮手。模組上有兩顆旋鈕：靈敏度、延遲時間，上課時把「延遲」逆時針轉到底，反應最快。

檢查點揮手時出現「偵測到有人」，停住不動幾秒後出現「恢復無人」。
3:00步驟 4

LM393 光敏模組

感測器腳位接到 Uno說明
AOA1類比輸出（讀數值）
DO不接本次不用
GNDGND接地
VCC5V電源

這個模組的針腳印刷順序是 AO、DO、GND、VCC，和其他感測器不同。上傳 範例程式\c04d-ldr。

動手：先記下平常的數字，再用手把感測器完全遮住，記下遮住的數字。這個模組越暗數字越大。

檢查點遮住感測器，數字明顯變大。門檻取「平常」與「遮住」兩個數字的中間值。

五、感測資料整合

約 3:30 – 4:30
3:30步驟 1

接電源軌

Uno 只有一個 5V 孔，四個感測器都要 5V，所以要用麵包板的電源軌分出去： 用公對公杜邦線把 Uno 的 5V 接到紅色電源軌、GND 接到藍色電源軌； 四個感測器的 VCC、GND 都改接到電源軌（母對公杜邦線）。訊號腳維持原本接法。

四個感測器合計約 90 mA（典型值估算），遠低於 USB 的 500 mA，不需要外接電源。

先量電源軌

有些 400 孔小麵包板的電源軌在中間是斷開的，左右兩半不通。 接線前用三用電表量一下兩端是否相通；斷開的話，左右兩半各自接一條 5V 和 GND。

3:50步驟 2

上傳整合程式，逐一驗收

上傳 範例程式\c05-sensor-node，開序列埠監控視窗，會看到每秒一行：

{"t":31,"h":43,"pir":0,"dist":23,"light":280}

五個欄位依序是：溫度、濕度、人體（1 有人）、距離（公分，-1 量不到）、光線（越暗越大）。 逐一確認：呵氣 → h 變大；手靠近超音波 → dist 變小；在人體紅外線前揮手 → pir 變 1；遮住光敏 → light 變大。

檢查點四個欄位都會隨動作變化。某個欄位不動，就是那個感測器還沒接好。

六、Node.js 與雲端

約 4:30 – 6:00
4:30步驟 1

讓電腦讀到資料

先關掉序列埠監控視窗（一個連接埠同時只能被一個程式使用）。 在教材的 雲端實作 資料夾開終端機：

# 列出連接埠，找出 Arduino 是哪個 COM
npm run ports

# 複製設定檔範本（Windows）
copy .env.example .env

用記事本開 .env，把 SERIAL_PORT=COM3 改成你的 COM 編號。

4:50步驟 2

填入 ThingSpeak 與 ntfy 設定

在 .env 填入這三個（等號後面不要有多餘空白）：

THINGSPEAK_WRITE_KEY=你的 Write API Key
NOTIFY_CHANNELS=ntfy
NTFY_TOPIC=你自己取的主題名稱

NOTIFY_CHANNELS=ntfy 表示只啟用 ntfy。NTFY_TOPIC 要和手機 App 訂閱的主題逐字相同。 NEAR_CM=30 是「距離小於幾公分就通知」，可以依現場調整。

5:10步驟 3

啟動並看三個去處

執行 npm start。終端機出現「已連上 COM」和「收到第一筆資料」就成功了。

去處一：瀏覽器開 http://localhost:3000 看即時數值、趨勢圖、通報記錄。
去處二：到 ThingSpeak 你的頻道看曲線（最短 15 秒才有一筆新資料）。
去處三：手放在超音波前 10–30 公分，手機應該收到「有東西靠近」。同一種通知 60 秒內只會發一次。

檢查點儀表板在跳、ThingSpeak 出現曲線、手機收到 ntfy 通知。

§4接線總表

四個感測器的 VCC 都接電源軌的 5V、GND 都接電源軌的 GND。訊號腳各自不同，不會衝突。

感測器訊號腳 → Uno程式
DHT11DATA → D2c04a-dht11
HC-SR04Trig → D4、Echo → D5c04b-hcsr04
HC-SR501OUT → D3c04c-pir
LM393AO → A1（DO 不接）c04d-ldr
四個一起c05-sensor-node

D0、D1 是序列埠專用，不要接任何東西，否則程式上傳不進去。

§5門檻要現場量，不要照抄

每個模組、每間教室的環境都不一樣。程式裡的數字只是範例。

感測器範例門檻怎麼訂
光敏400記下「平常」與「遮住」兩個數字，取中間值。本講師機平常約 280、遮住約 490，但教室偏暗時平常就可能超過 600。
距離30 公分先看空曠時的數字，再決定「多近算近」。設定檔的 NEAR_CM。
溫度32 °C先看室溫。室溫本來就超過門檻，就把門檻調高。

§6卡住的時候

照這個順序查：先連接埠，再接線，最後設定。九成的狀況都停在前兩項，先別懷疑雲端服務壞掉。

常見狀況速查

狀況常見原因怎麼辦
連接埠找不到、或上傳失敗（Access denied）USB 線只能充電；CH340 驅動沒裝；序列埠監控視窗或 Node.js 占用連接埠換 USB 線；關掉監控視窗並停掉 Node.js；npm run ports 確認埠號
某個欄位一直不變那個感測器沒接好，或沒有電拔掉其他模組，一個一個單獨測
全部感測器都沒反應5V 或 GND 沒接到電源軌，或電源軌中間斷開量電源軌兩端；斷開的話左右各接一條線
距離一直是 -1HC-SR04 沒收到回波：VCC、GND、Trig、Echo 其中一條沒接好先查四條線，再把手放在前面 10–30 公分
溫濕度一直是 0 或讀取失敗DATA 沒接在 D2，或讀太快對照接線；程式間隔不要小於 1 秒
ThingSpeak 沒資料Write Key 貼錯（貼成 Read Key）、多了空白，或送太快重貼 Write API Key；耐心等 15 秒
手機沒收到通知主題名稱兩邊不一致；手機沒開通知權限；同一種通知 60 秒內不重複逐字比對 .env 與 App 的主題；看儀表板「通報記錄」有沒有「已送達 ntfy」

想一個人先試雲端那一半？

在 雲端實作 執行 npm run mock：用模擬訊號跑完整條流程，不需要板子。 板子還沒接好、或網路有問題時，先用它把「板子」和「雲端」隔離開來找原因。

§7回家可以往哪裡走

四條路都沿用今天的接線與程式骨架，差別只在多接一個零件或多改幾行。

方向怎麼做
天暗自動通報照距離那一段的寫法複製一次，改成光線超過門檻就通知。
加輸出裝置加蜂鳴器或 LED，讓裝置自己也會叫（要另外購買）。
換成問答機器人改用 LINE 的回覆訊息：免費，代價是要架 webhook。
讓裝置自己上網換 ESP32 就不必接電腦，但要先過機關 WiFi 那一關。
分享成果時，請分享 ThingSpeak 的圖表網址，不要分享 Write API Key 或 ntfy 的主題名稱 —— 它們是密碼。截圖前先遮起來。
