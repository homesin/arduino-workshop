查的順序

資料的路線是一條線：感測器 → Uno → USB → Node.js → 儀表板 / ThingSpeak / ntfy。哪一關斷了，後面全部都看不到。所以：

  1. 先查連接埠（最常見）
  2. 再查接線與電源
  3. 最後才查設定檔（Key、主題名稱）
一個原則：一次只改一個地方，改完馬上測。同時改好幾個，好了也不知道是哪個修好的。

1第 1 關：電腦看得到板子嗎

怎麼確認：在 雲端實作 資料夾執行 npm run ports，看有沒有名稱含 CH340 或 USB-SERIAL 的連接埠。Arduino IDE 選單裡括號寫 (USB) 的那一個也是它。

狀況原因怎麼辦
清單裡沒有 CH340／USB 的埠USB 線只能充電；USB 孔問題；CH340 驅動沒裝換一條 USB 線、換 USB 孔；重跑一鍵安裝（驅動那一列要是 ✓）
整塊板子都不亮USB 線沒接好或壞掉換線
IDE 的開發板名稱顯示 Unknown正常：IDE 不認得相容板用 Select other board and port… 手動選 Arduino UNO 與 (USB) 那個埠
上傳失敗，出現 Access denied 或 port 相關錯誤連接埠被占用：序列埠監控視窗還開著，或 Node.js 還在跑關掉序列埠監控視窗；其他視窗的 Node.js 按 Ctrl + C；再上傳
上傳失敗、埠號正確D0 或 D1 接了線拔掉 D0、D1 上的線
一個連接埠同時只能有一個程式使用：序列埠監控視窗、Node.js、上傳，三者擇一。

2第 2 關：板子有在說話嗎

怎麼確認：Arduino IDE 打開序列埠監控視窗，速率選 9600 baud。

看到什麼原因怎麼辦
黃色警告 Not connected還沒選開發板與連接埠選好 Arduino UNO 與 (USB) 埠
亂碼（��）速率不是 9600右下角改成 9600 baud
空白，什麼都沒有板子上不是會輸出的程式；或剛好錯過開機那一句確認已上傳 c03b 或 c05；按板子上的 Reset 鈕

3第 3 關：每個感測器有讀數嗎

怎麼確認：上傳 c05-sensor-node，監控視窗每秒一行 {"t":..,"h":..,"pir":..,"dist":..,"light":..}。逐個動手：呵氣、揮手、靠近、遮光。

症狀可能原因怎麼辦
全部感測器都沒反應5V 或 GND 沒接到電源軌；電源軌中間斷開；5V、GND 接反檢查 Uno 到電源軌的兩條線；紅藍線對調要立刻拔 USB；軌道有缺口就左右各接一條
某一個欄位一直不變那個模組沒接好或沒電拔掉其他模組，一個一個單獨測（用 c04a～c04d）
溫度、濕度一直是 0 或讀取失敗DATA 沒接 D2；讀太快對照接線；程式間隔不要小於 1 秒
距離一直是 -1HC-SR04 沒收到回波：VCC、GND、Trig（D4）、Echo（D5）有一條沒接好；前方太空曠先查四條線；手放前面 10–30 公分再看
人體紅外線亂跳剛插電還在暖機等約一分鐘；HIGH 會維持好幾秒，這是正常的
光敏數字和直覺相反LM393 是越暗越大正常現象，不是壞掉

4第 4 關：Node.js 收得到資料嗎

怎麼確認：在 雲端實作 資料夾 npm start，終端機要出現「收到第一筆資料」，儀表板右上角綠點「已連線」。

狀況原因怎麼辦
Access denied 或 Resource temporarily unavailable序列埠被占用關掉監控視窗；別的 Node.js 視窗按 Ctrl + C
一直沒有「收到第一筆資料」.env 的 SERIAL_PORT 填錯；Arduino 沒上傳 c05重跑 npm run ports 確認埠號，改 .env 後重啟；重新上傳 c05
打不開 localhost:3000程式沒在跑；埠號被改過看終端機印出的網址
想先確認程式本身沒問題—npm run mock（不需要板子）或 npm run selftest
mock 能練到什麼：沒有板子、板子壞了、還沒接線時，用 npm run mock 照樣能把儀表板、ThingSpeak、ntfy 整條流程練完。

5第 5 關：ThingSpeak

狀況原因怎麼辦
啟動摘要顯示「ThingSpeak — 未設定（略過）」THINGSPEAK_WRITE_KEY 是空的或沒存檔貼上 Write API Key，存檔，重啟
頻道 Entries 一直是 0Key 貼成 Read Key；多了空白；還沒滿 15 秒重貼 API Keys 頁最上面的 Write API Key；等 15 秒
終端機「失敗」次數增加Key 錯誤，或連不上 ThingSpeak確認網路；先看本機儀表板
某個 Field 沒圖建頻道時沒勾選該 FieldChannel Settings 勾選並儲存
為什麼是 15 秒：免費版最短 15 秒才收一筆，程式已內建節流（再多留 2 秒餘裕，實際約每 17 秒一筆），調得更短也不會更快。

6第 6 關：ntfy 手機通知

狀況原因怎麼辦
手機沒收到主題名稱兩邊不一致；沒允許通知；同一種通知 60 秒內只發一次逐字比對 .env 的 NTFY_TOPIC 與 App 裡訂閱的主題；開啟 App 的通知權限；看儀表板「通報記錄」
網頁收得到、手機收不到手機沒訂閱同一個主題在 App 清單確認主題名稱
手動測試被拒絕（429）送太快，被頻率限制；教室共用同一個網路出口等一兩分鐘再試，不要全班同時狂按
靠近了卻完全沒通知NOTIFY_CHANNELS 沒寫 ntfy；.env 沒存檔；NEAR_CM 門檻太小檢查 .env；看儀表板距離數字，調整 NEAR_CM
主題名稱等於密碼：不要貼給別人、不要用 test 之類好猜的名字。

7上課驗收清單

全部打勾，就完成了這台環境監測站：

異常測試（看儀表板與手機的反應）

  • 手靠近超音波：距離變小，小於門檻時手機通知
  • 手遮住光敏：光線數字變大
  • 在人體紅外線前揮手：人體從 0 變 1，通報記錄出現「偵測到有人經過」
成功的樣子：手靠近超音波時，手機在幾秒內響。
成果分享：分享 ThingSpeak 的圖表網址，不要分享 Write API Key 或 ntfy 主題名稱。
回家後延伸：光線超過門檻也通知（天暗通報）、加輸出裝置（蜂鳴器、LED，需另外購買）、換 ESP32 讓裝置自己上網。
