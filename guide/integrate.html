整合版上傳與驗收（c05）

四個感測器一起讀、每秒送出一行 JSON：怎麼上傳、怎麼看、怎麼確認四個欄位都會變。

步驟
  1. 開始前：接線要全部接好
  2. 開啟並上傳 c05-sensor-node
  3. 看懂序列埠的那一行
  4. 逐一驗收：四個欄位都會變
  5. 程式在做什麼（millis 與事件）
  6. 常見錯誤
前提：四個感測器都照 麵包板與四感測器接線 接好，VCC 接紅軌、GND 接藍軌。 不知道怎麼開檔、上傳，先看 開啟範例程式與安裝函式庫。

1開始前：接線要全部接好

整合版把前面四支程式合在一起，所以四個感測器要同時接著，腳位和第四章完全一樣，不用重接：

感測器訊號腳電源
DHT11DATA → D2VCC → 紅軌（5V）
GND → 藍軌
HC-SR501（人體紅外線）OUT → D3
HC-SR04（超音波）Trig → D4、Echo → D5
LM393（光敏）AO → A1（DO 不接）
接線前先拔掉 USB：接好、檢查完再插回去。

2開啟並上傳 c05-sensor-node

  1. 先關掉序列埠監控視窗（開著會讓上傳失敗）。
  2. File → Open（Ctrl + O），走到 桌面 → arduino-workshop → 範例程式 → c05-sensor-node，開啟 c05-sensor-node.ino。
  3. 確認右上角是 Arduino UNO 和正確的 COM 埠。
  4. 按左上角 →（Upload）（Ctrl + U），等右下角出現 Done uploading.。
  5. 按 Ctrl + Shift + M 開序列埠監控視窗，速率選 9600 baud。
需要 SimpleDHT：c05 要讀 DHT11，用到 SimpleDHT 函式庫。一鍵安裝已經裝好；編譯說找不到時，看 開啟範例程式與安裝函式庫 的步驟 4。
檢查點：右下角出現 Done uploading.，監控視窗第一行是 # sensor node ready。

3看懂序列埠的那一行

之後每秒一行，長得像這樣（數字會依你的環境不同）：

# sensor node ready
{"t":31,"h":43,"pir":0,"dist":-1,"light":659}
{"t":31,"h":43,"pir":0,"dist":-1,"light":659}
欄位意思來自
t溫度（°C，整數）DHT11
h濕度（%，整數）DHT11
pir1＝有人、0＝沒人HC-SR501
dist距離（公分）；-1＝沒收到回波（前方太空曠、超出量程，或沒接好）HC-SR04
light0～1023，越暗數值越大LM393

# sensor node ready 那行不是 JSON，只是讓你看到板子活著；第六章的 Node.js 會自動略過它。

溫濕度更新比較慢：DHT11 每 2 秒才讀一次，其他每秒都讀。所以 t、h 會連續兩行一樣，是正常的。

4逐一驗收：四個欄位都會變

一個一個動，看對應的欄位有沒有跟著變：

你做的事應該看到
對著 DHT11 呵氣h 變大（t 可能也略升）
手放在超音波前 10～30 公分，慢慢移近移遠dist 跟著變小、變大
在人體紅外線前揮手pir 變 1，過幾秒自己變回 0
用手遮住光敏模組light 變大
檢查點：四個欄位都會動，整合才算成功。某個欄位不動，就是那個感測器還沒接好，看步驟 6。
人體紅外線剛插電要暖機約 1 分鐘：這段時間 pir 讀值不準，先做別的欄位。

5程式在做什麼（millis 與事件）

為什麼不用 delay：四個感測器的節奏不同。delay(1000) 會讓整塊板子睡一秒，這一秒內其他感測器都沒人看。整合版改用 millis()：每一圈都很快，只是看一眼時鐘，時間到了才做事。

unsigned long now = millis();           // 開機到現在幾毫秒
if (now - lastDht >= 2000) {            // 離上次讀 DHT11 超過 2 秒才讀
  lastDht = now;                        // 記下這次的時間
}
if (now - lastSend >= 1000) {           // 每秒送一行
  lastSend = now;
}

事件：通知不能每一圈都響。範例的做法是只在「剛跨過門檻」的那一刻算一次，例如距離從 30 公分以上變成 30 公分以下；低於門檻的那段時間不重複算。第六章的手機通知就靠這個寫法才不會響個不停。

6常見錯誤

看到什麼原因怎麼辦
只有 # sensor node ready，之後一行 JSON 都沒有DHT11 一次都沒讀成功（程式要讀到溫濕度才開始送）檢查 DHT11 的 VCC、GND、DATA → D2，再按板子上的 Reset
某個欄位一直不變那個感測器的線沒接好，或沒有電拔掉其他模組，一個一個單獨測
全部都沒反應5V 或 GND 沒接到電源軌，或電源軌中間斷開量電源軌兩端；斷開的話左右各接一條線（看 接線教學）
dist 一直是 -1沒收到回波先查 VCC 與 Trig、Echo 有沒有接反；前方不要太空曠
t、h 一直不變DHT11 讀取失敗時，程式沿用上一次的值檢查 DATA 線是否鬆脫
上傳失敗（Access denied、unable to open port）序列埠監控視窗還開著，搶同一個連接埠關掉監控視窗，再按上傳
監控視窗是亂碼速率不是 9600右上方選 9600 baud
下一章要用 Node.js 讀這個連接埠：一個連接埠同時只能被一個程式使用，進入第六章前，記得先關掉序列埠監控視窗。
