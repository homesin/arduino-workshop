其他通知管道：LINE、Discord、Telegram、Slack、Email

課堂上用 ntfy，課後想換別的，程式都已寫好，只差憑證與設定。

內容
  1. 先看總覽：每種管道要準備什麼
  2. LINE：官方帳號＋Messaging API
  3. Discord：建立 Webhook
  4. Telegram：BotFather 機器人
  5. Slack：Incoming Webhook
  6. Email：寄信通知
  7. 測試：npm run mock

1先看總覽：每種管道要準備什麼

管道要準備什麼.env 要填注意
ntfy（課堂用）自訂主題名稱，不用註冊NTFY_TOPIC主題名稱像密碼，別外流
LINE官方帳號＋Messaging API 頻道LINE_CHANNEL_ACCESS_TOKEN每月 200 則免費；群發給 N 位好友扣 N 則
Discord頻道的 Webhook 網址DISCORD_WEBHOOK_URL校園網路可能封鎖 Discord，先實測
TelegramBotFather 建的機器人＋你的 Chat IDTELEGRAM_BOT_TOKEN
TELEGRAM_CHAT_ID		要先對機器人說一句話
SlackIncoming Webhook 網址SLACK_WEBHOOK_URL需要有 Slack 工作區
EmailSMTP 主機與信箱密碼SMTP_HOST、SMTP_USER、SMTP_PASS、EMAIL_TO不即時，容易進垃圾信
LINE Notify 已停止：它在 2025 年 3 月 31 日結束服務，網路上舊的「LINE Notify 教學」都不能用。現在要用 LINE，走官方帳號的 Messaging API（第 2 步）。
這些管道程式都已經寫好（在 雲端實作\src\channels）。你只要做兩件事：把憑證填進 .env，再把管道名稱加進 NOTIFY_CHANNELS。

2LINE：官方帳號＋Messaging API

需要自己申請，約 15 分鐘。完整圖文步驟見 LINE 通知教學，這裡列重點：

  1. 先到 LINE Official Account Manager 建立 LINE 官方帳號，再到「設定 → Messaging API」按啟用 Messaging API（2024 年 9 月起不能再直接在 developers.line.biz 建立頻道）。完整圖文步驟見 LINE 通知教學。
  2. 啟用後到 developers.line.biz 用同一組帳號登入，找到頻道。
  3. 頻道的 Messaging API 分頁最下面，Channel access token 按 Issue，複製。
  4. 用手機掃 QR Code，把官方帳號加為好友，沒加好友收不到。
  5. 填進 .env：
    LINE_CHANNEL_ACCESS_TOKEN=貼上你的token
NOTIFY_CHANNELS=ntfy,line
額度：官方帳號輕用量方案每月 200 則免費（2026-09 查證，會變動）。程式用「群發」，加你好友的人越多，每則扣越多；程式預設一天最多送 20 則。

3Discord：建立 Webhook

最省事的一種：不用開發者帳號，也不用裝額外程式。

這一種已實測可行，有完整圖文教學：Discord 通知教學（註冊、建伺服器、Webhook、疑難排解）。下面是重點。
  1. 在你自己的 Discord 伺服器，對想收通知的文字頻道按「編輯頻道」，找到「整合」→「Webhook」→「建立 Webhook」。
  2. 按「複製 Webhook 網址」。
  3. 填進 .env：
    DISCORD_WEBHOOK_URL=貼上網址
NOTIFY_CHANNELS=ntfy,discord
Webhook 網址等於密碼：知道的人都能往你的頻道發訊息。不要貼在截圖、簡報或公開網站上。外洩了就刪掉那個 Webhook 重建。
學校網路：校園網路有可能把 Discord 列入封鎖，換場地前先在現場實測。

4Telegram：BotFather 機器人

免費，幾乎沒有額度限制。要填兩個值：機器人的 Token，和你自己的 Chat ID。

這一種已實測可行，有完整圖文教學：Telegram 通知教學（註冊、操作、疑難排解）。下面是重點。
  1. 在 Telegram 搜尋 @BotFather，送出 /newbot，依指示取名，最後會給你一串 Token。
  2. 用手機對你的新機器人說一句話（任何字都行）。沒先說過話，機器人不能主動傳訊息給你。
  3. 用瀏覽器開 https://api.telegram.org/bot<你的Token>/getUpdates，在回傳資料裡找 message → chat → id，那個數字就是 Chat ID。
  4. 填進 .env：
    TELEGRAM_BOT_TOKEN=貼上Token
TELEGRAM_CHAT_ID=貼上數字
NOTIFY_CHANNELS=ntfy,telegram
送不出去：401 是 Token 錯了；400 是 Chat ID 錯了，或你還沒對機器人說過話。

5Slack：Incoming Webhook

學校或團隊本來就在用 Slack 的話最方便，通知直接進工作頻道。做法和 Discord 幾乎一樣。

這一種已實測可行，有完整圖文教學：Slack 通知教學（建立工作空間、建 App、Incoming Webhook、疑難排解）。下面是重點。
  1. 到 api.slack.com/apps 建立 App（Create an App → From scratch → Pick features），加入 incoming-webhook 權限，按 Create and Install 並授權頻道；再到 App 的 Incoming Webhooks 頁複製網址。官方說明見 Incoming Webhooks。
  2. 填進 .env：
    SLACK_WEBHOOK_URL=貼上網址
NOTIFY_CHANNELS=ntfy,slack
Slack 的操作畫面常改版，選單名稱以官方說明為準。Webhook 網址同樣要當密碼保管。

6Email：寄信通知

人人都有信箱，不必裝 App。但手機不一定即時跳通知，自動寄出的信也容易被丟進垃圾信，適合當備援，不適合當唯一管道。

  1. Gmail 要用應用程式密碼，不是登入密碼：到 Google 帳戶的應用程式密碼產生 16 碼（沒開兩步驟驗證時這個選項不會出現）。
  2. 填進 .env：
    SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=你的信箱
SMTP_PASS=16碼應用程式密碼
EMAIL_TO=收信的信箱
NOTIFY_CHANNELS=ntfy,email
SMTP_PASS 只放在自己的 .env：不要貼給任何人，也不要上傳到網路。程式預設一天最多寄 50 封。

7測試：npm run mock

  1. 存檔 .env。NOTIFY_CHANNELS 用逗號分隔，可以同時開好幾種，名稱不分大小寫。
  2. 在終端機執行 npm run mock，等一則警報。
  3. 對應的手機或信箱收到訊息，就成功了。
檢查點：沒設定憑證的管道，終端機只會印出「預演」字樣的內容，那是程式在說「還沒設定，所以沒真的送」，不是錯誤。
預演模式會真的送：只要 .env 裡有憑證，npm run mock 就會真的送出通知。測試前確認收件的是你自己。
