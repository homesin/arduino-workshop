雲端實作啟動教學

用 Node.js 把 Arduino 的資料送到儀表板、ThingSpeak 與手機通知。先用模擬訊號練一遍，再接真的板子。

步驟
  1. 開啟終端機並進入專案資料夾
  2. 先用模擬訊號跑起來（不需要 Arduino）
  3. 看本機儀表板
  4. 停止程式
  5. 接真的 Arduino：找連接埠
  6. 設定 .env
  7. 正式啟動
  8. 接上 ThingSpeak 與 ntfy
  9. 常見錯誤
整體圖：Arduino 每秒送一行 JSON 給電腦，Node.js 在中間分成三個去處：本機儀表板（看現在）、ThingSpeak（存起來）、ntfy 手機通知（出事叫人）。

1開啟終端機並進入專案資料夾

用 VS Code 開啟課程資料夾，選單 終端機 → 新增終端機，再進到 雲端實作 資料夾：

cd 雲端實作
套件已經裝好：課前 install.cmd 已替你執行過 npm install。資料夾裡有 node_modules 就不用再裝；沒有的話，才在這個資料夾執行 npm install。

2先用模擬訊號跑起來（不需要 Arduino）

沒有板子、板子壞了、還沒接線，都可以先用 mock 把整條流程練一遍：

npm run mock

終端機會印出設定摘要，接著每秒收到一筆模擬資料：

  Arduino 雲端實作 · Node.js 中樞
  ─────────────────────────────────
  資料來源      模擬訊號（--mock，沒有接板子也能跑）
  即時儀表板    ✔ http://localhost:3000
  ThingSpeak    — 未設定（略過）
  警報通知      — 一家都沒設定（會在終端機預演）
  ─────────────────────────────────
  按 Ctrl+C 結束。要用 Arduino IDE 上傳程式前，一定要先結束這支程式。

[19:17:51] 儀表板已開在 http://localhost:3000
[19:17:51] 模擬訊號啟動（每秒一筆）
[19:17:52] 收到第一筆資料，接下來每秒一筆：溫度 27°C、濕度 59%
檢查點：看到「收到第一筆資料」，就表示 Node.js 正常運作。
先看設定再跑：如果你的 .env 已經填了 ThingSpeak Key 或 ntfy 主題，mock 也會真的送出資料和通知。這是為了讓你練完整流程，但全班同時跑要記得是用各自的主題，不要共用。

3看本機儀表板

瀏覽器開 http://localhost:3000（埠號以終端機印出的為準），右上角出現綠點「已連線」就代表資料正在進來。

往下捲：

畫面位置對應的感測器怎麼看
溫度、相對濕度DHT11大數字是現在的值，曲線是最近兩分鐘
超音波測距HC-SR04平常顯示「正常」；小於門檻（預設 30 公分）會變成警示；量不到顯示 -1
人體紅外線HC-SR501顯示「無人」或「有人」
光線LM393數字越大越暗
通報記錄以上事件例如「偵測到有人經過」

4停止程式

回到終端機按 Ctrl + C 結束。換成真板子之前一定要先結束。

5接真的 Arduino：找連接埠

Arduino 用 USB 接上電腦，先把 Arduino IDE 的序列埠監控視窗關掉（一個連接埠同時只能有一個程式使用）。然後執行：

npm run ports

會列出電腦上所有連接埠，Arduino 通常是名稱含 CH340 或 USB-SERIAL 的那一個：

偵測到的連接埠：
  COM3     Intel(R) Active Management Technology - SOL (C
  COM1     通訊連接埠 (COM1)
  COM2     通訊連接埠 (COM2)
  COM4     USB-SERIAL CH340 (COM4)  ← 很可能是這個

把上面的埠號填進 .env 的 SERIAL_PORT。
你的埠號不一定是 COM4：上面是講師電腦的結果。每台電腦、每個 USB 孔可能不同，以你自己跑出來有箭頭的為準。如果完全沒有 CH340 的那一行，多半是 USB 線只能充電，或驅動沒裝好。

6設定 .env

先把範本複製成你的設定檔（資料夾裡已經有 .env 就跳過這步）：

copy .env.example .env

用 VS Code 打開 .env，至少改這一行（等號前後不要有空白）：

SERIAL_PORT=COM4

其餘常用設定都有預設值，通常不用動：

設定意思預設
SERIAL_PORTArduino 的連接埠COM3
NEAR_CM距離小於幾公分算「有東西靠近」30
ALERT_COOLDOWN_SEC同一種警報幾秒內不重複發60
THINGSPEAK_INTERVAL_SEC上傳 ThingSpeak 的間隔（免費版最短 15）15
PORT儀表板網址的埠號3000
.env 是你的私人設定：裡面會放 Write API Key 和 ntfy 主題名稱，都等於密碼。不要傳給別人、不要貼到群組、截圖前先遮起來。

7正式啟動

npm start

這次「資料來源」會顯示序列埠，而不是模擬訊號。Arduino 要先上傳過 c05-sensor-node 範例程式。

檢查點：終端機出現「收到第一筆資料」，儀表板的數字跟著感測器變。手遮住光敏、手靠近超音波，看數字有沒有反應。
要重新上傳 Arduino 程式前：先在終端機按 Ctrl + C 停掉 Node.js，否則會因為連接埠被占用而上傳失敗。

8接上 ThingSpeak 與 ntfy

在 .env 再填兩樣，填的是你自己的，不要用別人（包含講師）的：

THINGSPEAK_WRITE_KEY=你的 Write API Key
NTFY_TOPIC=arduino-你的隨機字串
NOTIFY_CHANNELS=ntfy
  • Write API Key 從哪裡來：請看ThingSpeak 註冊教學。
  • ntfy 主題怎麼取、手機怎麼訂閱：請看ntfy 安裝與訂閱教學。

存檔後重新啟動（Ctrl + C 再 npm start），設定摘要裡「ThingSpeak」那一行會從「— 未設定（略過）」變成「✔ 已啟用」，通知那一行也會改變。

驗收：儀表板在跳、ThingSpeak 頻道出現曲線（最短 15 秒才有一筆新資料）、手靠近超音波時手機收到通知（同一種通知 60 秒內只發一次）。

9常見錯誤

狀況可能原因怎麼辦
Access denied 或 Resource temporarily unavailable序列埠被占用：Arduino IDE 序列埠監控視窗還開著，或 Node.js 已經在跑關掉監控視窗；其他終端機視窗的 Node.js 按 Ctrl + C
打不開 localhost:3000程式沒在跑，或 .env 的 PORT 改過看終端機印出的網址
終端機一直沒有「收到第一筆資料」SERIAL_PORT 填錯；Arduino 沒上傳程式重跑 npm run ports 確認埠號；重新上傳 c05-sensor-node
想練習但沒有板子—npm run mock
ThingSpeak 沒資料Write Key 貼錯（貼成 Read Key）、多了空白，或送太快重貼 Write API Key；耐心等 15 秒
手機沒收到通知主題名稱兩邊不一致；沒允許通知；60 秒內剛發過逐字比對 .env 與 App 的主題；看儀表板「通報記錄」
